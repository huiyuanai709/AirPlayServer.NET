AirPlayServer.NET Native AOT 宿主

本目录是一次发布包。版本和平台写在 VERSION.txt。
程序是 GPL-3.0-only，因为进程内编进了 FairPlay。
对应源码是本仓库里同名的 git tag。包里没有配对种子，也没有密钥材料。

先确认二进制还能跑自检：

  Windows:  AirPlayServer.Host.exe --self-check
  Linux:    chmod +x AirPlayServer.Host
            ./AirPlayServer.Host --self-check

自检通过会打印 self-check ok。--help 打印全部参数。

和 TapClock 一起用（Windows，主路径）：

  1. 先启动 TapClock，让它监听 ATBF（TCP 42125）。点击仍走 TapClock 自己的 TCP 42123。
  2. 再启动本宿主，不要加 --demo-frame：
       AirPlayServer.Host.exe --screen 480x1040 --model iphone-15-pro --tapclock 127.0.0.1:42125
  3. iPhone 在同一局域网里发现接收端并开始镜像。

镜像连上或断开时可以通知 TapClock（不在这里点击控制中心）：

  浏览器打开 http://127.0.0.1:7099/ ，打开「向 TapClock 发送镜像事件」。
  默认 POST http://127.0.0.1:5088/api/integrations/airplay/events
  断连先等 3 秒。这 3 秒里又连上就不会发 disconnected。
  可选请求头 X-TapClock-Token。状态可查 GET /api/status。
  --no-notify 关闭页面。--tapclock-events 直接打开事件。配置在 session-notify.json。

多台手机可以同时镜像。默认不限制路数。需要上限时用 --max-mirrors N（正整数，没有硬上限；超过 N 路返回 503）。
每一路单独窗口、单独 session_id。新手机不会踢掉已经连上的那一路。
--tapclock-dir 按镜像数据对端 IP 写文件，例如 mirror-192.168.5.20.jpg。
还没有对端时写 mirror-unknown.jpg。ATBF 头仍然不含来源地址，日志会写 IP。

--screen 是 /info 里的广告分辨率，宿主默认 480x1040。
--model 是 TapClock 点击对齐的竖屏 UIKit 逻辑点（iphone-15-pro 为 393x852），不改广告。
--list-models 打印全部 slug。两个参数可以只写其中一个。

--h265 和 --hevc 是同一个可选开关，默认关闭，只收 H.264。
只有 HEVC 解码器真能打开时，mDNS 和 /info 的 features 才置上第 42 位（SupportsScreenMultiCodec）。
没有解码器时这个开关被忽略，日志用中文和英文写明，手机继续发送 H.264。
这个开关不改默认的 480x1040。较新的苹果设备只有在宣告的分辨率够高时才会改发 HEVC。
例如：
  AirPlayServer.Host.exe --h265 --screen 1290x2796 --model iphone-15-pro-max
Windows 先用 Media Foundation HEVC。没有 CLSID_CMSH265DecoderMFT（也没有可用的硬件 MFT）时改用 FFmpeg。
Linux 上 H.264 和 HEVC 都只走 FFmpeg。

FFmpeg 不在这个压缩包里，也没有链进程序。把共享库放在本目录，或装到系统路径。
认 FFmpeg 4.4 到 9（libavcodec 58–63，libavutil 56–61，libswresample 3–7）。
Windows：从 https://github.com/BtbN/FFmpeg-Builds/releases 下载 win64-lgpl-shared
（win64-gpl-shared 也可以；不要用 static）。n7、n8，以及当前带 avcodec-63.dll 的构建
（n9.0 或 master）都可以。把 bin 里的 DLL 全部拷到本目录。
至少要有同一版本的 avcodec-*.dll、avutil-*.dll、swresample-*.dll。
当前这组是 avcodec-63.dll、avutil-61.dll、swresample-7.dll。
HEVC 按名字 "hevc" 打开。FFmpeg 9（avcodec-63）里数字 id 173 是 FIC 不是 HEVC。
若日志出现 [fic @ ...] Zero slices found 和 ffmpeg-hevc send failed (Invalid data)，
DecodedFrames 会停在 0，窗口是黑的。那是旧二进制写死了 173，换这一版即可。
--h265 仍要加。--screen 1290x2796 只决定广告分辨率；实际帧高差 2 像素（1290x2794）不会让画面变黑。

暂停后窗口不再刷新、会话还在，并且日志是：

  Mirror sender resumed.
  Mirror geometry 720x1560 source 720x1560
  NV12 to BGRA is BT.709 full range (...)
  H.264 decoder is the Microsoft Media Foundation software decoder.

这是 Windows 软件 H.264，不是 HEVC，不需要 --h265，也不依赖旁边的 FFmpeg DLL。
720x1560 是手机这次的画面尺寸。软件解码器 drain 出第一帧之后会 flush，
再送回同一个关键帧，后面的帧继续画。旧版本只发 start-of-stream，窗口会停在这一帧。
Linux：sudo apt-get install ffmpeg
也可以把 libavcodec.so.N、libavutil.so.N、libswresample.so.N 放在本目录。
当前主版本是 libavcodec.so.63、libavutil.so.61、libswresample.so.7。
这些库是 LGPL-2.1-or-later，带 GPL 组件的构建则是 GPL。分发它们时要遵守该构建的许可证。
本程序是 GPL-3.0-only。更新不会删除你另外拷进来的 DLL / SO。

Linux 包用 Avalonia / X11 打开镜像窗口，不包含 Media Foundation。没有图形会话时加 --no-window。没有 FFmpeg 时可以用 --demo-frame 检查导出。窗口旁边的 libSkiaSharp / HarfBuzz 原生库要留在程序目录里。
linux-x64 包里的 airplayserver.service 是 systemd 草稿，不含 --seed。
把 AirPlayServer.Host 拷到 /usr/local/bin/ 后再启用。
这个二进制在 GitHub 的 ubuntu-latest 上构建，需要兼容的 glibc。

--seed 只留在内存里，不要写进单元文件或脚本后提交。
发布包不含 .pdb / .dbg 调试符号，运行不需要它们。

默认不检查更新；用 --update 手动更新。普通启动不访问 GitHub。
要更新时运行 --update 或 --check-update。版本以本目录的 VERSION.txt 为准。
有较新稳定版时，下载同一平台的 zip，能对上 SHA256SUMS.txt 就先校验，
再替换本目录里的程序和这些说明文件，然后重新启动。
已经是最新稳定版时，这两条只打印版本并退出，不启动接收端。
--no-update 仍然可以写，效果和默认一样，可以和其他参数一起用。
--auto-update 会在这次启动时检查。检查失败、GitHub 速率用完、校验失败或目录不可写时，
只记日志，继续跑当前这个程序。
--version 打印版本，不访问网络。
公开的 Release 不需要令牌。私有仓库请设置环境变量 GITHUB_TOKEN 或 GH_TOKEN。
