AirPlayServer.NET Native AOT 宿主

本目录是一次发布包。版本、平台和构建写在 VERSION.txt（flavor=lean 或 flavor=ui）。
程序是 GPL-3.0-only，因为进程内编进了 FairPlay。
对应源码是本仓库里同名的 git tag。包里没有配对种子，也没有密钥材料。

两种包，文件名不一样：

  lean  AirPlayServer.Host-<版本>-win-x64.zip
        AirPlayServer.Host-<版本>-linux-x64.zip
        没有 Avalonia、Skia、HarfBuzz。不打开镜像窗口。给 TapClock、无图形会话、systemd 用。
        --no-window 可以写，效果和默认一样。--help 和 --self-check 照常可用。

  ui    同名再加 -ui，例如 AirPlayServer.Host-<版本>-win-x64-ui.zip。
        带 Avalonia 镜像窗口。旁边的 libSkiaSharp / HarfBuzz 原生库要留在程序目录里，不要删。
        没有嵌入 Inter 字体（没有中文，悬停数字用系统字体）。
        Windows 这一包用软件绘制，不含 av_libglesv2.dll。
        没有图形会话时加 --no-window。Linux 的 ui 包需要 libX11。

--update 只下载和当前构建相同的那一种，不会把窗口包换成精简包，也不会反过来。
v0.1.14 的更新器只认不带 -ui 的文件名，所以从那一版执行 --update 会落到精简包。
要窗口请另外下载 -ui，解压到新目录。换种类时不要只靠 --update，旧的 Skia 库不会被删掉。

先确认二进制还能跑自检：

  Windows:  AirPlayServer.Host.exe --self-check
  Linux:    chmod +x AirPlayServer.Host
            ./AirPlayServer.Host --self-check

自检通过会打印 self-check ok。--help 打印全部参数。

和 TapClock 一起用（Windows，主路径）：

  1. 先启动 TapClock，让它监听 ATBF（TCP 42125）。点击仍走 TapClock 自己的 TCP 42123。
  2. 再启动本宿主，不要加 --demo-frame：
       AirPlayServer.Host.exe --screen 480x1040 --model iphone-15-pro --tapclock 127.0.0.1:42125
  3. iPhone 在同一局域网里发现接收端并开始镜像。

镜像伴音（type 96，AAC-ELD）写到系统默认播放设备。Windows 用 WASAPI。Linux 需要 PulseAudio 或 ALSA，没有就只出画面、日志里会写明。音量用手机的 SET_PARAMETER，GET_PARAMETER 回当前分贝。

带窗口的包可以订阅镜像上的按下和抬起。--webhook 可重复，也写在配置页的「点击地址」里。事件名 mirror.click，不发给手机。说明和 JSON 见仓库 README。

镜像连上或断开时可以通知 TapClock（不在这里点击控制中心）：

  浏览器打开 http://127.0.0.1:7099/ ，打开「向 TapClock 发送镜像事件」。
  默认 POST http://127.0.0.1:5088/api/integrations/airplay/events
  断连先等 3 秒。这 3 秒里又连上就不会发 disconnected。
  可选请求头 X-TapClock-Token。状态可查 GET /api/status。
  --no-notify 关闭页面。--tapclock-events 直接打开事件。配置在 session-notify.json。

多台手机可以同时镜像。默认不限制路数。需要上限时用 --max-mirrors N（正整数，没有硬上限；超过 N 路返回 503）。
每一路单独窗口、单独 session_id。新手机不会踢掉已经连上的那一路。
--tapclock-dir 按镜像数据对端 IP 写文件，例如 mirror-192.168.5.20.jpg。
还没有对端时写 mirror-unknown.jpg。USB 一路写 mirror-usb-<序列号>.jpg。
ATBF 头仍然不含来源地址，日志会写 IP 或序列号。

有线画面是可选的，默认关闭：
  AirPlayServer.Host --usb
  AirPlayServer.Host --usb-udid <序列号或 UDID>
  AirPlayServer.Host --usb --allow-dual
这是 QuickTime-over-USB 协议的 C# 实现，用 libusb，不打开 Qt 窗口，也不依赖 QuickTime.app。
和无线 AirPlay 同时收。每台 USB 手机单独一路。--max-mirrors 把两种都算上，
而且启动时的无线监听已经占 1 个名额，所以 --max-mirrors 1 时 USB 开不出来。
同一台手机在两边设备名相同（忽略大小写）时，默认不再开第二路。--allow-dual 允许两路一起收。
USB 产品名经常只是 iPhone，和 AirPlay 里的名字不同，所以默认很少拦得住同一台。
USB 伴音是 ASYN EAT! 里的明文 LPCM（通常 48 kHz 立体声），写到系统默认播放设备。
Windows 用 WASAPI，Linux 用 PulseAudio 或 ALSA。打不开设备时只丢声音，画面继续。
无线 AAC-ELD 和手机音量增益保持原样。USB 没有 SET_PARAMETER，按样本原样播放。

需要 libusb-1.0，放在程序旁边或系统路径里：
  Windows  libusb-1.0.dll
  Linux    libusb-1.0.so.0   （apt install libusb-1.0-0）
  macOS    libusb-1.0.0.dylib
找不到 libusb 时只记日志，无线 AirPlay 照常。缺库和认领失败是两条不同的日志。

Windows 驱动（win-x64 包里有 windows-usb-setup.cmd 和 windows-usb-driver.ps1）：
  父设备保持 usbccgp。安装 Apple Devices（Microsoft Store）或 Apple Mobile Device Support。
  商店页面：https://apps.microsoft.com/detail/9np83lwlpz9k
  不要用 Zadig 把 Apple 复合父设备换成 WinUSB 或 libusbK。WinUSB 不能切换 USB 配置。
  一键：插上手机，双击 windows-usb-setup.cmd，在管理员提示里允许。
  脚本下载官方 libusb 1.0.30 的 libusb-1.0.dll，以及官方 libusb-win32 1.4.0.2，
  校验 SHA256 后，只给这一台 Apple 父设备装 UpperFilter（--device-id=该实例）。
  install-filter 只注册 libusb0 服务和 UpperFilter，不复制驱动文件。
  脚本会接着把官方 zip 的 bin\amd64\libusb0.sys 复制到
  %SystemRoot%\System32\drivers\libusb0.sys，并把同目录的 libusb0.dll 复制到 System32。
  复制后用 Test-Path 确认 .sys 存在，否则失败，不算安装成功。
  只有注册、没有这个文件时，设备管理器是代码 39（CM_PROB_DRIVER_FAILED_LOAD），
  手机只能充电，也不会弹出信任对话框。
  -Check 会把「UpperFilter 或服务已在、但 libusb0.sys 缺失」和「文件已就位」分开写。
  修复：重新运行 -Setup，或从官方 zip 的 bin\amd64 把 libusb0.sys 复制到上述目录。
  本包不附带 libusb0.sys，也不下载 Apple 的安装包。临时 zip 在确认文件之后删除。
  也可以：powershell -ExecutionPolicy Bypass -File .\windows-usb-driver.ps1 -Setup
  只检查：powershell -ExecutionPolicy Bypass -File .\windows-usb-driver.ps1 -Check
  只放用户态 DLL：powershell -ExecutionPolicy Bypass -File .\windows-usb-driver.ps1 -FetchLibusb -HostDir .
  已有官方 zip 时（管理员）：
    powershell -ExecutionPolicy Bypass -File .\windows-usb-driver.ps1 -InstallFilter -FilterZip C:\path\libusb-win32-bin-1.4.0.2.zip
  官方地址写在 windows-usb-driver.ps1 开头，也写在 docs/usb-windows.md。
  装完重新插拔，解锁并信任这台电脑，再加 --usb。
  libusb -12 表示配置切换不被当前驱动允许。-3 / -6 表示设备忙。-4 / -5 表示手机不在线上。
  libusb -1（LIBUSB_ERROR_IO）表示 libusb-1.0 已经列出这台 Apple 设备，但 libusb_open 失败。
  手机还在，列表也不是空的。不要卸载 Apple Devices。无线 AirPlay 不受影响。
  商店版 Apple Devices（AppleInc.AppleDevices）不注册传统的 Apple Mobile Device Service，
  也没有 Common Files\Apple\Mobile Device Support。AppleLowerFilter、AppleKmdfFilter、
  AppleMobileDeviceProcess.exe 或 AMDS32\MobileDevice.dll 在，就算 Apple 栈已安装。
  源码说明：docs/usb-windows.md。

  资源管理器里能看到手机（MTP/存储）不等于 QuickTime 镜像。那是 PTP。
  镜像要的是类 0xFF 子类 0x2A。--usb 会主动发控制传输 0x40/0x52，让手机重新枚举。
  这不是控制中心的隔空播放，也不会替你点「屏幕镜像」。
  Apple Devices 或 Apple Mobile Device Support 仍然需要。本包不下载 Apple 的安装包。
  父设备已经是 usbccgp 并且装了 libusb0 UpperFilter，也不能代替 Apple 那一层。
  --usb 开着却没有有线会话时，日志大约每 30 秒写一次原因，而不是每秒刷屏：
    libusb 列表是空的；看见 Apple 但没有 mux（0xFF/0xFE）也没有 QuickTime；
    打开失败并带 libusb 错误码；或者当前只有 MTP/PTP，将发送 0x40/0x52。
  描述符里已经有 mux 或 QuickTime 的手机仍按原来的路径打开，不会被当成「只有 MTP」。

--screen 是 /info 里的广告分辨率，宿主默认 480x1040。
--model 是 TapClock 点击对齐的竖屏 UIKit 逻辑点（iphone-15-pro 为 393x852），不改广告。
--list-models 打印全部 slug。两个参数可以只写其中一个。

--h265 和 --hevc 是同一个可选开关，默认关闭，只收 H.264。
只有 HEVC 解码器真能打开时，mDNS 和 /info 的 features 才置上第 42 位（SupportsScreenMultiCodec）。
没有解码器时这个开关被忽略，日志用中文和英文写明，手机继续发送 H.264。
这个开关不改默认的 480x1040。较新的苹果设备只有在宣告的分辨率够高时才会改发 HEVC。
例如：
  AirPlayServer.Host.exe --h265 --screen 1290x2796 --model iphone-15-pro-max
Windows 先用 Media Foundation HEVC。没有 CLSID_CMSH265DecoderMFT（也没有可用的硬件 MFT）时改用 FFmpeg。
Linux 上 H.264 和 HEVC 都只走 FFmpeg。

FFmpeg 不在这个压缩包里，也没有链进程序。把共享库放在本目录，或装到系统路径。
认 FFmpeg 4.4 到 9（libavcodec 58–63，libavutil 56–61，libswresample 3–7）。
Windows：从 https://github.com/BtbN/FFmpeg-Builds/releases 下载 win64-lgpl-shared
（win64-gpl-shared 也可以；不要用 static）。n7、n8，以及当前带 avcodec-63.dll 的构建
（n9.0 或 master）都可以。把 bin 里的 DLL 全部拷到本目录。
至少要有同一版本的 avcodec-*.dll、avutil-*.dll、swresample-*.dll。
当前这组是 avcodec-63.dll、avutil-61.dll、swresample-7.dll。
HEVC 按名字 "hevc" 打开。FFmpeg 9（avcodec-63）里数字 id 173 是 FIC 不是 HEVC。
若日志出现 [fic @ ...] Zero slices found 和 ffmpeg-hevc send failed (Invalid data)，
DecodedFrames 会停在 0，窗口是黑的。那是旧二进制写死了 173，换这一版即可。
--h265 仍要加。--screen 1290x2796 只决定广告分辨率；实际帧高差 2 像素（1290x2794）不会让画面变黑。

暂停后窗口不再刷新、会话还在，并且日志是：

  Mirror sender resumed.
  Mirror geometry 720x1560 source 720x1560
  NV12 to BGRA is BT.709 full range (...)
  H.264 decoder is the Microsoft Media Foundation software decoder.

这是 Windows 软件 H.264，不是 HEVC，不需要 --h265，也不依赖旁边的 FFmpeg DLL。
720x1560 是手机这次的画面尺寸。软件解码器 drain 出第一帧之后会 flush，
再送回同一个关键帧，后面的帧继续画。旧版本只发 start-of-stream，窗口会停在这一帧。
Linux：sudo apt-get install ffmpeg
也可以把 libavcodec.so.N、libavutil.so.N、libswresample.so.N 放在本目录。
当前主版本是 libavcodec.so.63、libavutil.so.61、libswresample.so.7。

Linux 包不包含 Media Foundation。H.264 / HEVC 在运行时加载 FFmpeg。没有 FFmpeg 时可以用 --demo-frame 检查导出。
lean 不打开窗口。ui 用 Avalonia / X11 打开镜像窗口，没有图形会话时加 --no-window，并且需要 libX11。
linux-x64 包里的 airplayserver.service 是 systemd 草稿，不含 --seed。ui 包里的这份草稿带 --no-window。
把 AirPlayServer.Host 拷到 /usr/local/bin/ 后再启用。
这个二进制在 GitHub 的 ubuntu-latest 上构建，需要兼容的 glibc。

--seed 只留在内存里，不要写进单元文件或脚本后提交。
发布包不含 .pdb / .dbg 调试符号，运行不需要它们。
